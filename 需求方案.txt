SystemOneStudio 完整产品方案

一站式可视化决策模型训练平台
版本：V2.0 完整版
核心定位：让业务人员 30 分钟训出可用的决策模型

---

一、产品定位

1.1 一句话定位

SystemOneStudio 是面向业务人员的零代码决策模型训练平台。业务人员只需上传样本数据、选择场景模板，平台自动完成数据合成、模型训练、量化部署全流程，输出可直接对接业务系统的决策模型。

1.2 解决的核心问题

痛点 现状 SystemOneStudio 方案
定制成本高 训一个垂类模型需算法团队 2-3 个月 业务人员 30 分钟完成
样本不足 黑样本少、黑白不均衡 智能数据合成自动扩增
链路割裂 数据、训练、评测、部署各自为政 一站式全流程闭环
部署门槛高 需要工程师做量化和 API 封装 一键部署，自动生成 API
不可解释 模型输出黑盒，业务不敢用 输出判定依据和特征重要性
底座绑定 换模型要重写全流程 模型注册表 + 适配器，即插即用

1.3 目标用户

角色 需求 使用方式
业务人员（主力） 快速训出可用模型 向导式流程，一键操作
风控策略师 迭代优化决策规则 对比评测，偏好标注
数据分析师 探查数据质量 数据看板，质量报告
算法工程师 深度定制 高级模式，参数调优
运维人员 部署和监控 一键部署，API 管理

二、用户体验设计原则

这一章是本方案的核心。业务人员能不能上手，取决于以下 8 条原则是否落地。

原则 1：向导优先，画布可选

不要一上来就给拖拽画布。 业务人员面对空白画布会不知所措。

· 默认模式：向导模式。7 步向导，每步一屏，下一步按钮引导。
· 进阶模式：画布模式。熟悉后可切换到流程画布自由编排。
· 一键模式：极速模式。选择模板 + 上传数据 + 点开始，其余全自动。

三种模式共享同一套底层引擎，随时可切换。

原则 2：智能默认值，能不动就不动

每个配置项都必须有基于场景的智能默认值：

· 学习率：根据模型规模和数据量自动推荐
· 合成比例：根据黑白样本比自动计算
· 量化档位：默认 Q4_K_M（对齐 JEV）
· 训练轮数：根据数据量自动估算

业务人员只需改"必须改"的项，其他全部折叠在"高级设置"里。

原则 3：每一步都有即时反馈

步骤 反馈形式
上传数据 实时预览前 100 行 + 质量评分
数据合成 进度条 + 分布对比图实时更新
选择模型 显存占用预估 + 训练时长预估
训练中 loss 曲线实时刷新 + 预计剩余时间
评测 指标看板 + 与基线对比
部署 一键复制 curl 命令

原则 4：用业务语言，不用技术术语

技术术语 业务语言
LoRA 微调 快速风格适配
QLoRA 低显存快速适配
DPO 偏好对齐 决策优化训练
知识蒸馏 大模型能力迁移
Q4_K_M 量化 标准压缩（推荐）
分布拟合合成 智能样本扩增
特征重要性 关键判定因素

界面上只显示业务语言，鼠标悬停显示技术说明。

原则 5：错误可恢复，操作可撤销

· 每一步都可回退，数据不丢失
· 训练失败自动保存断点，可续训
· 参数配置支持"恢复默认"
· 误删项目 7 天内可恢复

原则 6：进度可见，等待不焦虑

· 长任务显示预计剩余时间
· 训练中可离开页面，完成后站内信 + 邮件通知
· 提供"训练期间可做的其他事"引导

原则 7：结果可解释，决策有依据

· 每个模型输出必须带 reason 字段
· 评测报告用业务语言解读，例如："该模型在 1000 个测试样本中，正确识别了 91% 的涉诈账户，误杀率为 4%"
· 提供对比视图：新模型 vs 旧模型 vs 基线模型

原则 8：模板开箱即用

预置行业模板，每个模板包含：

· 标准字段体系
· 标准标签规范
· 推荐模型和训练方法
· 默认评测指标
· 示例数据集

用户选择模板后，80% 的配置已自动完成。

  ↓

  ↓

  ↓

  ↓

六、JEV 对齐规范

6.1 JEV 规范附录

```yaml
jev_spec:
  version: jev-1.0
  
  input_template: |
    <system>
    你是一个专业的决策模型，负责对输入样本进行判定。
    </system>
    <task>
    根据以下特征，判断该样本是否属于风险样本。
    </task>
    <features>
    {features}
    </features>
    <output_format>
    请输出 JSON 格式：
    {"decision": "...", "score": ..., "confidence": ..., "reason": "..."}
    </output_format>
  
  output_schema:
    decision:
      type: string
      enum: [black, white, gray]
      description: 判定结果
    score:
      type: float
      range: [0, 1]
      description: 风险评分
    confidence:
      type: float
      range: [0, 1]
      description: 置信度
    reason:
      type: string
      max_length: 200
      description: 决策依据
  
  eval_baseline:
    quant: Q4_K_M
    latency_metric: p95_end_to_end_ms
    accuracy_metric: decision_accuracy
    target_latency_p95: 100
    target_accuracy: 0.90
```

6.2 JEV 兼容三级

等级 含义 底座要求 验证方式
L1 格式兼容 输入输出 JSON 结构一致 任意底座 Schema 校验
L2 格式 + 评测兼容 指标口径一致 任意底座 基准测试
L3 风格兼容 决策风格接近原生 JEV 推荐 Qwen 系 对比测试

6.3 JEV 兼容开关

拆成两个独立开关：

· jev_format_compat：控制输入输出格式和 API 结构
· jev_training_compat：控制训练范式、超参、评测口径

8.2 偏好数据生成流水线

DPO 需要 (prompt, chosen, rejected) 三元组。生成方式：

```text
种子数据 → SFT 冷启动 → 用 SFT 模型对种子样本多次采样
→ 正确判定作为 chosen，错误判定作为 rejected
→ 生成偏好对 → DPO 训练
```

或通过 Playground 的 A/B 选择人工沉淀偏好数据。
