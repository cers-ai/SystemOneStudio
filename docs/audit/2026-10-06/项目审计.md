# SystemOneStudio 项目审计

日期：2026-10-06。对象：当前工作区（含未提交改动），不是仅审查最后一个提交。本文记录事实；新需求、技术方案和开发计划均为待批准草案。

## 1. 项目真正要解决的问题

本项目的价值是让业务人员把自己的样本转成可试用、可接入、可追溯的三分类决策模型。交付物不是训练配置页面，也不是算法函数，而是“数据 → 有效训练 → 真实评测 → 可调用服务”的闭环。业务用户应只决定场景和数据，平台负责其余步骤并解释结果。

原需求把长期平台蓝图、MVP、技术选型、界面示例和性能愿景混在同一个文档中。实现因此同时扩张模型货架、训练方法、场景展廊、助手和编排，却没有建立面向用户的验收闭环。后续改造引入了真实基础设施，但依然用模块完成和测试通过代替产品完成。

## 2. 结论

“只有 Web 壳子”准确表达了使用体验，但不完全描述代码资产：数据算法、契约、SQLite、任务队列、训练后端、量化工具、推理客户端都已有代码。应保留有效资产，重建应用层衔接、执行可靠性和交互；全量重写会丢掉已有的不变量保护。

当前还不能按产品流程完成一次真实训练、评测、部署和预测。最严重的问题不只是没有本地 GPU，而是即使给现有 Worker 配 GPU，主流程也没有接完。

## 4. 本轮验证结果与边界

完整执行 `npm run verify`：lint、typecheck 通过；Web 45 个测试、术语库 56 个测试通过。Web 当前只有术语泄漏测试文件，没有用户流程交互测试。

完整执行 `npm run verify:py`：格式、lint、93 个源码文件 mypy 通过；877 passed、1 skipped、1 warning。跳过项为 GPU E2E。警告来自 FastAPI TestClient 的 httpx 使用方式。

`npm run build` 成功。原始日志见 `docs/audit/2026-10-06/`。这些数字是本次实际执行结果，不能推导为训练能力、模型效果或线上稳定性已验证。

启动了隔离临时数据库的 API 和本地前端，查看首屏与训练入口。接口探针只使用人工构造的非业务样本，不接触真实训练数据。本机无 NVIDIA GPU，未执行真实训练、量化、推理、延迟与显存验收。没有连接远程 GPU，也没有购买资源。

## 5. 原始需求里的矛盾与纠偏

- 第 12 章写二分类，第 6、10、13 章及 AGENTS 要求三分类：以 black/white/gray 为准。
- 第 8 章列了大量训练方法，第 10/13 章限制轻量底座与适配：本轮拟先验收一个底座、一种训练方法，多能力延期，不冒充已支持。
- “30 分钟”是原始目标，第 8 章的时长是示例/估算，均不是承诺或实测。本轮计时、报告，不直接宣传时限。
- reason 的 200 字符是上限，不是固定输出长度。因此不能仅凭上限推出延迟目标必然不可能；必须固定硬件、输入/输出长度、并发和计时边界后实测。原始 P95 目标仍待口径决策。
- 示例图里的隐私安全、相关性、特征权重不是算法已验证的事实。独立采样器不能叫做已实现相关性建模；输出 reason 也不能替代特征归因。
- JEV 仓库片段不是官方全文；双开关保留，不宣称 L2/L3。正式业务可用性还需要真实字段、真实样本和业务验收。
