# SystemOneStudio 开发计划 P3

版本：P3 · 2026-10-06 · **用户已批准，开始实施**。

本计划依据用户重新编制的 `SystemOneStudio-demo-v3.html` 和 `SystemOneStudio_判断模型技术方案_v3.md`。此前对 R2/T2/P2 的批准不视为对本次训练范式和范围变更的批准。规划阶段仅整理文档；用户批准后已进入实施，保留现有代码、数据和用户原始文件。当前进度见 docs/implementation/2026-10-06-p3.md。

## 1. 本阶段交付目标

做成真正可运行的零代码判断模型工作台：用户建立判断任务、导入带标签的决策样本、构造训练集、选用已验证配方、训练判断模型、校准并验证、导出或启动预测服务。

模型对固定候选给出概率；平台根据校准结果与阈值决定自动处理或交人工复核。第一版不生成自由文本理由，不用聊天式生成伪装判断模型。`gray` 是业务类别，`REVIEW` 是处理动作，两者分别展示。

沿用 V3 Demo 的项目展廊、深色与薄荷绿视觉、七步顶部导航、开放工作区和侧栏细节；使用真实接口、资产和任务状态替换演示数据。可浏览任何步骤，但执行动作必须满足依赖，不能用前端点击跳过训练和验证。

### 1.1 依据与冲突处理

优先顺序：用户最新指示 → 用户 V3 技术方案的产品/算法约束 → V3 Demo 的视觉与操作结构 → 原需求中未被替代的约束。Demo 中模拟数字和算法说明不是实测证据。

| 项目 | P3 基线 |

| 理由 | reason/evidence 可作为审计元数据；不进入 State，不强制在线返回 |
| 数据划分 | 按 group 划分；标准 70/10/10/10，小数据可显式采用 70/15/15 共享验证校准集 |

### 3.2 一体发行

一个产品、一个浏览器入口、一组持久目录，内部进程分责。训练 Worker 不能阻塞 API；在线模型运行时有独立生命周期。首版不引入 Redis/Celery/Kubernetes，不先做远程代理协议。

采用 Linux 容器发行：Linux GPU 主机直接运行；Windows GPU 主机以 WSL2 + Docker Desktop 为待验收部署路线。普通 Windows 浏览器也可访问任意控制面，不需要 Windows 专属客户端。CPU 本机用于数据库、接口、算法与界面验证；GPU 功能明确不可用，不展示假训练完成。

GPU 训练和在线服务共用显存时实行资源租约与排队，不能默认同时驻留两套模型。服务占用、释放与重新加载均显示真实状态；部署不预设能够无中断热切换。

## 4. 开工前必须确定的算法细节

### 4.1 底座与候选读出

Qwen 官方已发布 [Qwen3.5-2B-Base](https://huggingface.co/Qwen/Qwen3.5-2B-Base) 与 [0.8B-Base](https://huggingface.co/Qwen/Qwen3.5-0.8B-Base)。2B 是预训练底座，模型结构包括混合注意力与多模态部分；不能直接套用已有 Qwen2.5 加载类和 LoRA 模块名。Spike 必须确认文本路径、正确加载类、依赖版本、模型修订与许可证记录，按实际结构确定可训练层。

候选 token 在真实模板边界解析，必须稳定为单 token；不硬编码 A/B/C 的 token ID。训练、校准、评测、导出和在线请求共享 tokenizer revision、token map、模板与序列化版本。padding、截断与最后一个有效 decision slot 必须有覆盖测试，截断不得丢失候选和决策槽位。

候选 logits 采用稳定精度计算 softmax。CE 使用配置中的 label smoothing；Brier 使用原始 one-hot 目标及 `1/K` 归一化。默认 CE 权重 1、Brier 权重 0.2、smoothing 0.05，配置落盘。分别验证两项损失产生有效梯度，而非只验证损失数值相加。

使用原始 LM Head 并默认冻结；LoRA 的 r=16、alpha=32 为初始配方，实际 target modules 经适配确认。P0 不把自定义 head 的代码和导出格式混进基线路线。

### 4.2 数据、泄漏和小样本

canonical 样本包含 sample_id、group_id、state、target.choice、可选 evidence、source 与 metadata。字段角色映射是显式资产。标签、reason/evidence、预测结果、置信度及来源元数据不得进入 State；业务实体 ID 默认排除，需要有依据才能加入。

按 group 做确定性、尽量分层的划分；同实体、同源及其变体只能进入同一分区。先从真实种子冻结 test，再构造训练数据；训练进程不取得 test 文件路径。比例因 group 大小可能偏离目标，报告实际数量、类别与偏差，不拆组凑比例。

默认四分区 70/10/10/10。无法形成有意义的独立验证/校准分区时，可明确选择共享的 70/15/15，报告独立性降低；不靠未经定义的自动样本门槛悄悄切换。真实独立种子少于 200 条时标注“链路验证”，不批准业务效果；超过 200 条也不自动代表质量合格。

P0 构造只针对 train：类别平衡采样或可追踪重采样、候选顺序变换、字段顺序变换。候选顺序变化时同步重映射正确 token，评测再映射回业务 ID；不能只换文字不换标签。所有变体保留 group/source/build 血缘，重复样本不增加独立证据数。

### 4.3 校准、策略和冻结测试

Temperature 在 held-out cal 上以 NLL 拟合，使用 logT 参数和约束区间 [0.1,10]；保存拟合数据 hash、目标、配置和产物。比较 raw/calibrated NLL、Brier、ECE 与可靠性图；ECE 默认固定 15 个等宽概率桶，完整记录分桶口径。拟合失败、没有改善、样本不足都如实报告。

用户给出自动处理错误预算，默认 3% 是策略输入，不能宣称保证线上错误率。用 cal/valid 扫描阈值，在满足经验错误预算且有样本支持的候选中最大化 coverage，保存扫描表、自动样本数和误差不确定性。零自动样本的 error 是未定义；无可行解生成明确的 review_all 策略，不能以阈值 0.99 假装全人工。

AUTO 表示达到策略置信度的类别判断。gray 可以是高置信度业务灰类，但不会被解释成自动放行；业务含义与路由说明绑定 schema。输入错误、执行失败或模型不可用不能计入成功自动处理；分别统计错误与有效预测的覆盖率口径。

模型/序列化/token map/温度/策略先锁定为 MODEL_CANDIDATE_READY，再开放 frozen test 给 evaluator。测试输出分类、校准和风险覆盖指标，只作最终审计，不反向选择检查点、温度或阈值。

### 4.4 发布运行时与量化顺序

首先在合并模型的实际 Transformers runtime 上校准、锁策略并评测；合并前后和新进程加载结果也需一致性证据。不能仅测试 LoRA 包装模型就宣称合并模型可发布。

GGUF 转换及 candidate logits 获取属于单独技术探针。parity 使用从 valid/cal 划出的固定样本，不能用 test 调参数。比较 choice、一致概率和策略 action；V3 的 choice agreement ≥99%、平均概率偏差 ≤0.02 是初始工程门槛，报告真实结果及样本量，不等同业务质量承诺。

若量化改变概率，需要对该 runtime 单独拟合校准和策略，形成新 candidate，再运行冻结测试。不同 runtime 的 calibration/policy 不可混用。最终报告绑定实际发布包与 runtime hash；不得用先前未量化报告替代量化模型验收，也不得依据 test 结果迭代量化配置选优。

量化失败时可交付已验证的合并模型服务，GGUF 状态保留不可用及原因。本计划建议把这一点作为 P0 范围批准内容；若要求首版必交 GGUF，则未通过该门槛不能完成首版交付。

## 5. 实施工作包与依赖

先后顺序：批准 → W0 → W1 技术 Spike → W2/W3/W4 → W5/W6 → W7/W8 → W9。界面设计规范可在 Spike 期间整理，但训练主链集成必须等技术路线通过。每个后端工作包交付时同步接入对应步骤，W9 负责整体验收。

### W0：保护现场、恢复可验证基线

- 记录用户文件、未提交代码与数据的 hash、diff 和备份，不 reset、不覆盖、不归因于本轮实现。
- 修复已知前端路由/术语键和 Python 格式问题，执行完整 verify/build；失败逐项解决。
- 对旧场景、Run、模型和数据库做迁移盘点；旧生成模型标为 legacy，只读保留。
- 冻结 V3 契约目录和命名规则，区分训练完成、候选就绪、已验证、已导出和服务运行。

完成证据：基线检查日志、改动归属清单、可恢复备份、旧数据读取检查。这里只恢复工程基线，不把通过测试当成训练成功。

### W1：CLI 判断模型技术 Spike（Sprint 0，首要门槛）

- 在真实 GPU 上锁定 torch/Transformers/PEFT 等兼容版本，隔离 GPU extra/镜像依赖。
- 验证默认 2B 文本加载、candidate token resolver、slot logits、LoRA 层及非零梯度。
- 用带真实标签与 group 的小型数据完成训练、最佳 checkpoint、合并、新进程读出、温度、策略、冻结测试。
- 记录 CE/Brier 梯度与训练曲线、候选映射、显存峰值、耗时、数据分区、错误实例及全部版本。
- 0.8B 是第二组合验收，不因 2B 成功就自动标记可用；GGUF 提前做可行性探针，失败不阻塞合并模型基线。

交付：spike_report.md、training_config.yaml、token_map.json、calibration.json、threshold_policy.json、evaluation.json、merged model manifest 和可复现 CLI。

门槛：真实训练及合并重新加载通过，CE+Brier 确实参与梯度，校准策略可复现。效果未达业务目标时注明仅技术链路成立；GPU 不可用则 W1 待验收，可继续独立 CPU 工作，不宣称 Sprint 0 完成。

### W2：领域契约、持久化、项目展廊

- Project、DecisionSchema、Dataset、DatasetBuild、Recipe、Job、ModelVersion、Calibration、Policy、Evaluation、Service、Artifact 全量持久化。
- SQLite WAL 与事务，接入 Alembic；现有 SQL 迁移先识别并建立基线，禁止直接初始化覆盖数据库。
- project CRUD、schema 新版本、资产关联、列表过滤搜索、详情、删除范围与错误契约；OpenAPI 生成前端类型。
- 展廊显示真实任务类型、阶段、数据/模型版本、校准策略、实测摘要与更新时间；筛选与连续输入不丢焦点。

门槛：多个项目并存；重启后保留；上游修改产生新版本；legacy 不自动进入 V3 发布路径。

### W3：导入与冻结数据（步骤 1–2）

- 名称描述与判断问题/候选含义；字段角色推荐、明确确认、CSV/JSONL 校验与预览。
- canonical serializer、缺失/标签/重复/group 检查、可选不可逆脱敏。
- 真实种子分组划分与清单冻结，样本数和各类分布实际展示；小样本与缺类报告。
- 上传错误可定位行列并修正；同文件重复提交保持幂等、保留来源。

门槛：无标签泄漏；变体不跨分区；合成数据不进入 test；训练拿不到 test；刷新后映射、数据和划分可恢复。

### W4：真实训练集构造与配方（步骤 3–4）

- 实现三项 P0 构造和 lineage，提供前后类别分布、增量与独立种子数量。
- 控制构造倍率及样本规模，完整存储随机种子与候选重映射；不制造不存在的外部合成质量指标。
- 配方绑定数据版本、schema、模型 revision、模板、token map、序列化和 loss；高级参数展开查看。
- 环境探针确认 CUDA、加载能力、空间、可写缓存与依赖；返回 READY/PREPARING/UNSUPPORTED 及真实原因。

门槛：配方可复现，参数真正传到 trainer；只有已验收组合可执行。快速推荐不能绕过数据契约确认。

### W5：可监管的真实训练（步骤 5）

- 从 Spike 抽取正式 trainer，Worker 使用 JobSupervisor 启动独立进程。
- 排队、GPU 租约、阶段、stdout/stderr、heartbeat、退出码、错误原因和真实曲线统一落盘。
- 取消先优雅退出再强制结束；确认进程退出才释放资源。进程识别包含启动时间/命令与任务身份，不只用 PID。
- 检查点保留优化器、调度器、随机状态与配方指纹；仅匹配配置可恢复。不支持的恢复给明确原因。
- API/Worker 重启后识别存活、孤儿或中断任务；不把旧 heartbeat 当成仍在运行。
- 训练完成后自动合并并登记 candidate，不需要手工补数据库；离开工作台不影响执行。

门槛：成功、失败、取消、恢复、重启均有实测；没有产物时不能登记成功版本。

### W6：校准、阈值与真实验证（步骤 6）

- 对绑定候选执行温度拟合、阈值扫描、报告与不可变版本保存。
- 分类指标：Accuracy、Macro-F1、逐类指标、混淆矩阵；校准指标：Brier/ECE/NLL 与可靠性图。
- 策略指标：risk-coverage、所选阈值、自动处理数/错误数、复核比例、样本支持和预算满足情况。
- 稳健性：同样本六种候选顺序映射后对比、字段顺序、缺字段、已有边界样本及高置信错误。
- 最终模型、温度与策略锁定后，evaluator 独立读取 frozen test，记录模型包和所有配置 hash。
- 零分母、缺类、未计时、执行失败都区分“未测量/不可计算/失败”，不能返回满分。

门槛：raw/cal 对照真实；策略可复现；测试未用于调参；报告和错误样本可追溯。不要求所有校准实验必然改善。

### W7：发布 runtime、模型包与服务（步骤 7）

- 固定 schema 的 `/v1/predict` 返回 trace、版本、choice、完整候选概率、confidence、AUTO/REVIEW 与 policy 标识。
- 线上预处理和训练序列化一致，概率与策略实现唯一；参数不允许客户端偷偷改 schema 或阈值。
- 包含合并权重全分片、config、完整 tokenizer、schema、token map、serializer、calibration、policy、eval、lineage、checksum、API schema 和 README。
- 新进程在不依赖训练目录/联网下载的条件下加载模型包并预测。
- 可选 GGUF 通过转换、logits 与 parity gate 后发布，独立绑定 runtime/cal/policy。
- 服务 STARTING/RUNNING/STOPPING/STOPPED/FAILED 以进程与健康检查为准；导出成功不等于服务已运行。

门槛：与离线同样本的 choice/probs/action 一致；真实启动/停止/失败状态；实测冷启动、端到端延迟、吞吐、RAM/VRAM。记录输入长度、batch、并发、预热、硬件和测量边界，不沿用生成 token 吞吐口径。

### W8：工作区迁移与一体部署

- 一致性备份 SQLite 与资产清单，校验 hash；训练/写入期间使用明确的快照屏障或数据库备份机制。
- 恢复先在临时目录完整校验，处理安全路径与缺文件，再事务切换；不导入旧 PID/运行态。
- 新节点重映射 workspace/cache 路径，恢复所有领域资产与血缘；恢复后服务默认停止，探针通过再启动。
- Compose、持久卷、离线模型缓存、日志和 GPU extra 明确；Web/API 单入口。
- Linux GPU、Windows WSL2/Docker GPU 分别验收，记录驱动/WSL/容器条件；CPU 本机单独验证可用范围。

门槛：租期结束前可备份；在新目录/节点恢复后重新加载并预测一致；冷部署和有缓存启动均记录真实耗时。

### W9：完整用户旅程与视觉验收

- 用用户自定义任务从展廊创建，一次导入，依次构造/训练/校准/测试/发布，过程中不通过脚本补资产。
- 浏览器验收多项目切换、刷新、返回展廊、后退前进、连续搜索、上传重试、日志查看、取消恢复与服务启停。
- 比对 V3 Demo 的各步骤截图；验证正常、空、失败、排队、小样本、未测量与过期状态。
- 无助手/模板假入口，无可点击但无实现的模型/方法，无硬编码成绩和动画成功。
- 完成完整验证、GPU报告、安装和恢复说明、已验证能力清单与剩余限制。

门槛：A01–A10 的证据齐全，用户可独立复现。流程真实可用与业务效果达标分别作结论。

## 6. 版本、状态与失效规则

项目阶段是 DRAFT / DATA_READY / RECIPE_READY / TRAINING / MODEL_READY / CALIBRATED / VALIDATED / RELEASED 的摘要；Job 和 Service 使用各自状态机，不能用一个布尔值替代所有完成情况。

| 修改 | 处理 |
|---|---|
| 仅项目名称/描述展示文字 | 更新项目资料，已有冻结资产保留原审计快照 |
| 判断问题、候选含义、字段角色、序列化 | 新 schema/数据版本，下游历史可查，新链需重建训练 |
| 新增种子或改变 group/split | 新 dataset/build，重新冻结测试清单，下游沿旧版本仍可查 |
| 配方、模型修订、候选 map | 新 recipe/job/model，不覆盖旧检查点 |
| 温度拟合或策略预算 | 新 cal/pol/candidate，重新验证并发布；不直接改运行服务 |
| 量化档位/runtime | 新 runtime candidate，重新 parity/校准/策略/最终评测 |

重复点击使用幂等键，阶段事件有递增序号，前端支持断线补读。上游新版本使当前编辑链的下游显示“需要重新执行”；既有已发布版本保持完整只读血缘，不能混入新资产。

## 8. 交付节奏与停止条件

- Sprint 0：W0/W1，证明真实候选训练范式；CPU环境可准备契约、算法与视觉规范。
- Sprint 1：W2–W6，项目到校准验证的产品主链，每步同步接 UI。
- Sprint 2：W7–W9，发布、迁移、一体部署和完整体验验收。
- Sprint 3/4：另行批准质量增强及 RLCD-like，不能让其侵入 P0 关键路径。

暂不承诺日历日期、训练耗时和性能数字。W1 取得实际底座兼容性、GPU规格、训练/加载测量后，再给剩余工作包的工程量与交付日期估算。它们不能由 Demo 的计时动画或历史测试数推导。

停止条件明确：候选 token 无稳定映射、模型加载或梯度不成立时停止该组合并报告；没有 GPU 时停止真实训练验收；量化不可用时只开放已经通过的合并模型路径；没有可行阈值时采用 review_all；测试不达业务要求时保留失败报告，不通过换测试集宣称达标。
