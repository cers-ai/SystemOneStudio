# SystemOneStudio 开发计划

> 2026-10-06 用户补充：GPU 主机可能运行 Windows，不限定 Linux 宿主。部署首选复用同一套 Linux 容器：Linux 直接运行，满足 NVIDIA / WSL2 条件的 Windows 主机通过 Docker Desktop 运行。Windows 原生 Python 与推理工具链作为独立待验证路线，不宣称已兼容。当前优先交付单 HTML 交互 Demo，待界面反馈后继续业务实现。

版本 P2，2026-10-06，已于 2026-10-06 获用户整体批准。依据 `需求重整.md` R2、`技术方案.md` T2 和用户最新五项意见。第一阶段一次交付“Web 七步工作台 + 一体 GPU 应用 + 真训练验证 + 导出部署”，实施已获授权；先在本机 Docker Desktop 验证 CPU 可用链路，GPU 环节另行实测。

## 1. 相比上一计划

- 删除 Windows 专属应用、跨机协调器、SSH 隧道任务协议、多节点管理作为首版工作包。
- 替换反诈模板路径为用户名称/描述与通用种子 Schema，不依赖反诈真实字段或业务模板库。
- 七步向导与开放工作台是主体验，不把两个输入后的全自动流程作为首版唯一验收。
- 智能助手退出第一阶段，纳入入口/API/依赖解绑和历史配置保护。
- 增加发行镜像、冷/有缓存部署、模型导出独立加载、关租前工作区保存与恢复验收。
- 同一 Qwen 适配器内验证轻量底座与 LoRA/QLoRA 选择，只开放实测可用组合。

一体部署减少跨机复杂度，不能把 GPU 依赖、数据有效性与恢复的必要工作也省掉。旧 38–63 工程日估算基于两机方案，本轮撤回，不继续当新版承诺；在安装探针与首条真训练完成后，按剩余工作量重新估算。

## 2. 工作包

| 包 | 工作 | 依赖 | 完成门槛 |
|---|---|---|---|
| W0 | 批准范围与现有改动保护 | 整体批准 | 快照未提交改动；确定首条非反诈绑定数据契约、支持 GPU 环境、发行方式与持久目录 |
| W1 | 一体发行镜像与环境探针 | W0、GPU可用 | 从源码正确构建锁定 GPU 栈，正确入口与进程监视；实际 GPU 短训练/内核探针；记录冷部署和缓存启动 |
| W2 | 七步沉浸工作台设计 | W0 | 同一空间的七步交互稿、顶栏、参数/日志抽屉、失败/过期/恢复状态与视觉组件规范 |
| W3 | 控制主体/本地执行器/领域状态 | W0 | 队列与执行进程分离；Job/Run/事件一致；字段/任务契约与前端类型生成；自定义场景、不可变资产、幂等 |
| W4 | 种子与真实合成 | W3 | CSV上传修复、标签/依据映射、Schema、脱敏预览、固定划分、条件扩增、分布/来源/风险报告 |
| W5 | 真实训练与产物 | W1、W4 | 统一提示与场景语义；配置传到 trainer、validation与恢复；合并、压缩、加载、自动登记 |
| W6 | 真实测试验证与服务 | W5 | test实际推理、全量分母报告、错误案例、内部试用服务、平台predict、独立部署生命周期 |
| W7 | 导出与租期保存 | W3、W5、W6 | 模型包下载、独立环境加载；一致工作区备份/导入；新节点重映射与校验 |
| W8 | 工作台接入与助手退出 | W2、W3–W7 | 七步全部可操作、导航与依赖分开、刷新/恢复、模型/方法选择、完整视觉；助手入口/API/依赖解绑 |
| W9 | 完整现场验收与文档交付 | W1–W8 | 非反诈绑定场景从名称/描述走通全部步骤，GPU和浏览器证据、取消/恢复、导出/恢复、准确安装说明 |

推荐实现顺序：W0 → W1 环境与 W2 设计 → W3 → W4 → W5 → W6 → W7 → W8 → W9。界面按每个可用后端动作逐段接入，W8是最终整合验收，不是等全后端结束才开发页面。

先完成基线 Qwen1.5B/LoRA，再验证同族 3B/QLoRA。没有适配节点或组合失败时保留具体原因，不能以未验收选项填满模型货架。

## 3. 内部检查点

C0：发行方式可运行。真实租赁 GPU 节点使用镜像启动，训练依赖、CUDA、缓存与推理内核探针均有证据；不是 CPU mock。

C1：前三步完整。用户填名称描述、上传一次、查看规范化结果、执行真实扩增；刷新仍在原运行；未识别标签/缺依据给可修复提示。

C2：训练与验证完整。选择组合与参数确实生效；后台训练与产物登记连续；真实test报告和单样本试用不需要测试助手补库。

C3：交付完整。下载模型可独立加载；API真实启停；工作区导出后能在新节点恢复；七步工作台视觉/行为验收，第一版无助手。

这些是开发期间发现风险的检查点，任一未完成都不能宣称第一阶段交付。

## 4. 验证策略

每次实现改动按顺序完整执行 `npm run verify`、`npm run build`、`npm run verify:py`。契约/API变更先运行类型生成。新增测试面向真实断点、用户行为和资产不变量，不能先删旧保护性测试让结果变绿。

| 范围 | 需要证明 |
|---|---|
| CPU/接口 | 上传multipart、中文标签、role排除、参数穿透、自定义场景、同事务状态、文件幂等、取消/恢复、场景与审计持久化 |
| 合成 | 只访问train；类别与依据一致；无随机重贴标签；约束、重复与关联结构检查；不支持任务能说明 |
| 浏览器 | 七步导航、当前建议、开放回看、草稿保存、上游修改与下游待重算、报告/试用/导出部署；关键空/失败态 |
| GPU | 发行环境、训练与checkpoint、合并/压缩/加载、真正评测、业务HTTP、可用模型/方法组合 |
| 租赁交付 | 冷部署、有缓存重启、模型下载完整性、工作区备份、重建节点导入/启动 |

## 5. 故障矩阵

| 情况 | 正确行为 |
|---|---|
| 数据未标注/标签未知/缺判定依据 | 保存草稿并定位问题，不造标签、reason或confidence |
| 合成不支持/依据无法验证 | 不自动产生不可信样本；解释原因，允许使用种子继续 |
| 缺驱动/模型/空间 | 开始前明确阻断或显示准备状态，不能长期假排队 |
| 重复开始/合成/导出 | 幂等执行，不重复GPU任务、不覆盖已提交资产 |
| Worker失败 | Run/Job一致失败，业务原因/日志可读，从有效资产恢复 |
| 关闭浏览器 | 服务器任务继续，重新进入原工作台 |
| 服务器重启 | 对账，明确中断/可恢复，不沿用旧PID或SERVING |
| 取消 | 取消中 → 执行进程停止证据 → 已取消，释放GPU槽位 |
| 上游编辑 | 新版本，历史不覆盖，下游标记待重新生成 |
| 推理输出错误/超时 | 记录失败、原始输出与分母，不补造“成功”预测 |
| 关租前备份 | 确认运行状态，导出一致工作区，下载并校验后再由用户释放机器 |
| 新机器恢复 | hash/schema校验，重新解析路径和进程状态，模型依赖能核对 |

## 6. 完整验收脚本

1. 全新受支持GPU服务器使用发行镜像和配置启动，记录镜像/驱动/依赖/模型revision及各准备耗时。
2. 浏览器创建自定义场景，只填名称描述；不选择反诈模板，不配置助手。
3. 上传通用表格种子，确认输入、三类标签和依据，查看脱敏预览、质量与划分；不二次上传。
4. 执行数据合成，核对真实syn资产、候选样例与标签/依据关系；test仍仅seed。
5. 选择已验证底座与训练方法，接受推荐参数；观察真实训练、合并和Q4产物，验证自定义参数穿透。
6. 等待期间切回数据/配置查看，关闭浏览器再回来；同一执行继续。
7. 测试验证阶段自动生成真实报告，单条在线试用返回实际决策与依据。
8. 下载模型包，在兼容独立环境加载并预测；在平台启动私有API，复制curl调用固定版本。
9. 跑一次取消/恢复与一次阶段失败重试；验证状态、日志与产物一致。
10. 导出工作区，在另一干净的受支持环境导入，验证历史、数据hash、模型资产与重新启动服务。
11. 对七步工作台的宽屏/常用桌面、键盘操作、失败/空/过期状态完成视觉与交互验收。
12. 提供测试证据与局限：人工构造样本只证明流程；真实业务效果仍须真实数据独立验证。

## 7. 交付物

发行镜像与版本锁、单份部署配置、安装/检查/启动说明、GPU环境与通用流程报告、七步工作台、模型交付包格式、工作区导出恢复能力与使用说明、故障处理与备份清单。

实现阶段生成 `docs/acceptance/<date>/`：执行事件、环境、hash、训练/资源/预测测量、评测分母与错误、浏览器截图、独立加载/恢复记录。未验证项标未验证，不制造报告。

## 8. 本轮范围与延期

第一阶段不做：Windows客户端、远程代理网络模式、业务模板库、智能助手、任意画布、自由文本通用高质量合成、多模型族、DPO/蒸馏/QAT、集群、多租户、云资源自动释放。

轻代理是合理的后续路径：只在常驻控制节点确有需要时，将本地执行接口封装为受限服务，再实现跨机传输/断线恢复。第一版不为了“以后可能分机”提前交付整套远程控制平台。

本轮三份方案已按意见修订，整体仍待批准。批准后开始W0；本轮不连接GPU、不购买资源、不改变业务代码。Q1/Q3按新需求的明确范围处理，既不宣称性能达标，也不宣称官方JEV完整兼容。
