# SystemOneStudio 本阶段需求重整

> 2026-10-06 用户补充：GPU 主机可能运行 Windows，不限定 Linux 宿主。部署首选复用同一套 Linux 容器：Linux 直接运行，满足 NVIDIA / WSL2 条件的 Windows 主机通过 Docker Desktop 运行。Windows 原生 Python 与推理工具链作为独立待验证路线，不宣称已兼容。当前优先交付单 HTML 交互 Demo，待界面反馈后继续业务实现。

版本 R2，2026-10-06，已于 2026-10-06 获用户整体批准。依据：原始 `需求方案.txt`、项目审计及用户本轮五项意见。最新用户指示优先：取消 Windows 产品绑定，先做用户自定义场景，不做业务模板与智能助手。已批准实施；当前先评审单 HTML 交互原型。

## 1. 本阶段产品

一个通过浏览器操作的决策模型训练工作台。用户定义场景、上传种子样本、合成数据、选择底座与训练方法、执行训练、测试验证，最后导出模型或启动服务。

第一版以单台 Linux GPU 服务器的一体部署为推荐交付方式：一个产品、一个入口、一份部署配置。浏览器可在 Windows、Linux 或其他系统使用，控制节点本身不与 Windows 绑定。控制面与执行模块职责分开，分机轻代理作为后续部署方式，不作为第一版必须同时完成的两套产品。

目标同时包括：真实闭环、可恢复、极简操作、沉浸工作台与一致的视觉品质。示例证明软件可运行，真实留出样本证明模型效果；两种证据分别报告。

## 2. 对上一版方案的修订

| 项目 | 本轮决定/建议 | 对第一版的影响 |
|---|---|---|
| 控制面 | Web 控制面，操作系统无关 | 去掉 Windows 专属凭据、网关、协调与安装假设 |
| 部署 | 推荐 GPU 服务器一体部署 | 不先开发远程任务传输、隧道、节点管理等完整系统 |
| 执行模块 | 单独进程负责执行，通过明确接口与控制面衔接 | 重任务不阻塞 Web；以后可封装成轻代理 |
| 场景 | 用户填写名称、描述 | 不绑定反诈，不建设场景模板库，不要求先填业务字段清单 |
| 流程 | 七步向导 + 开放工作台 | 不再以“两个输入后全自动”作为唯一主模式 |
| 合成 | 独立可操作步骤，提供默认扩增建议、预览与报告 | 不藏在后台，不把随机贴标签的样本当有效合成 |
| 模型/训练 | 在“训练配置”中选择，默认推荐；只开放已验证组合 | 不展示未经验证的选择；高级超参数折叠 |
| 助手 | 第一阶段退出产品范围 | 无聊天栏、服务商设置、模型密钥或助手依赖 |
| 模板/画布/多节点 | 延期 | 工作台开放不等于自由 DAG 编排 |
| JEV | 双开关保留在高级设置，现有片段格式验证 | 不建设 L2/L3 或以规范缺失阻断普通业务闭环 |

本阶段继续是三分类决策模型，不扩张成任意大模型训练平台；场景可自定义，输出仍遵循已有 decision/score/confidence/reason 底线。

## 3. 七步主流程

### 1）定义场景

只填写名称和描述。描述说明“要判断什么、输入是什么、结果如何理解”，提供简短写作提示，不调用助手自动猜业务规则。场景代码 sc_* 和版本自动生成，创建项目/运行的技术细节不要求用户另行操作。

暂无业务模板和场景展廊；通用示例用于理解数据格式，不能自动替用户定义真实业务。名称和描述只定义任务语义，不能替代正确的标签和判定依据。

### 2）上传种子

第一阶段先支持 CSV。允许普通特征列 + 标签/依据列，也允许 input/decision/reason 的规范化形式。上传后自动识别列、字段类型和三类映射；用户只处理歧义。数据预览、脱敏、缺失检查、三类分布与数据划分都在此步骤完成，不另立复杂配置页。

有监督决策训练需要正确结果。首条验收样本包含 decision 和可核验 reason；未知标签必须修正，不能默认 black。若上传只有标签而无依据，保存数据并给出可恢复提示，在补充依据或明确并确认可执行规则后才能宣称解释训练有效。不能用同一句通用 reason 或固定 confidence 凑数。

字段角色为：模型输入、目标标签、目标依据、可选评分监督、关联标识、忽略列；自动排除 label/reason/score/confidence/origin 等目标字段，避免答案泄漏。场景名称描述之外的 Schema 从上传推导，不要求提前填写 32 个业务字段。

### 3）数据合成

显示 seed 训练部分的分布、推荐扩增量与用户可调整项，一键执行并持久化 syn_*。展示真实数量、分布、样例、重复率与能测量的风险信息。合成不足以测量的项目明确写未测量，不显示安全满分。

合成只从训练分区生成，保留特征与标签及依据的关系。第一版对表格型输入做可验证的条件扩增：整行/同类联合采样，受字段约束的轻微扰动；涉及规则边界与判定依据时同步校验。不能把不同类别的特征独立拼接后随机赋标签。无法证明扰动后标签/依据仍成立时，不自动改写该样本。

自由文本先不承诺通用高质量语义合成：不支持的字段/任务要说明并允许跳过，不引入额外付费大模型依赖。无有效扩增或无必要时，用户可以“使用种子数据继续”。端到端验收必须含真实合成路径，跳过只是受控可用性出口。

### 4）训练配置

底座卡片、训练方式卡片、推荐配置摘要放在一屏。选择模型和方法后，检查 GPU、缓存、空间与数据适配；明确“需要下载/准备中/可训练”。学习率、batch 等在高级设置，业务用户可以不改。

先用 Qwen2.5-1.5B-Instruct + LoRA 建立验收基线；本阶段围绕同一 Qwen 适配器验收 1.5B/3B 与 LoRA/QLoRA 的可运行组合。资源不足或没有实测的组合不开放选择。训练方式使用 ui-terminology 的业务文案，技术名在提示中。无 DPO/蒸馏/QAT/多模型族承诺。

### 5）训练

明确的“开始训练”动作。展示真实训练步数、loss、阶段、耗时和资源；合并、压缩、产物检查自动执行，不增加人工步骤。可查看日志、取消和在支持的 checkpoint 上恢复。

关闭浏览器不终止任务；服务器任务由执行进程管理。服务器停止/销毁与浏览器关闭不是一回事，不能承诺服务器释放后训练仍继续。

### 6）测试验证

产物可加载后自动执行冻结 test 的真实预测，结果落盘。用户进入此步查看性能、格式、三类指标、错误案例，并使用自定义样本或留出样本进行在线测试。单条试用需要的内核由系统内部启动，不要求先点击正式部署。

性能指标先展示，效果其次。报告包含全量分母、失败率、整体有效判定率与合规回答条件准确率。缺标签、分母不足和未测量分别说明；试用输出的 score/confidence 未校准时明确是模型自报值。

### 7）导出部署

提供两个并列、独立动作：下载交付包；启动/停止私有 API 服务。不把“下载文件”和“服务上线”合并为一个虚假完成状态。

默认产物包含 Q4_K_M GGUF、模型/场景元数据、校验和、输入输出 Schema、调用示例、评测报告；adapter/合并权重可按需下载。下载包要能在兼容运行环境加载验证，不能只有一个缺少元数据的权重文件。

服务只有进程、健康检查和业务请求均通过才显示可调用。提供平台真实 `/v1/predict` 与固定版本，不直接把 llama-server 的端口当业务 API。

## 4. 向导 + 沉浸工作台

全程在同一个模型工作台完成。顶部固定阶段导航：

`场景 → 种子数据 → 数据合成 → 训练配置 → 训练 → 测试验证 → 导出部署`

当前阶段与建议下一步清楚可见，中央为当前主要工作区，右侧为可收起的参数/摘要抽屉，底部为可展开的日志与任务进度；助手面板取消。项目列表是进入工作台的入口，不在每一步重新创建项目。

```text
┌ 场景名称 / 当前版本 ───────── 保存状态 / 执行环境 ┐
│ 场景 · 种子数据 · 数据合成 · 配置 · 训练 · 验证 · 导出 │
├─────────────────────────────┬───────────┤
│                             │ 参数/摘要 │
│      当前阶段的开放工作区     │ 可收起    │
│      预览、报告、图表或试用   │           │
│                             │           │
├─────────────────────────────┴───────────┤
│ 日志与任务进度（可展开）          建议下一步 / 主操作 │
└─────────────────────────────────────────┘
```

向导是建议路径，工作台是持久空间。允许回看已完成步骤，查看未就绪页面及其原因；资产未就绪时限制执行动作，而不是禁止导航。修改上游配置创建新版本并让下游显示待重新生成，不覆盖已经训练的历史资产。显示“草稿已保存”与“结果已产出”的区别。

不在第一阶段引入拖拽画布、任意步骤重排或多任务 DAG。检查/调整与推荐默认共用同一条状态链。极速自动执行作为后续快捷操作，不再为了保留旧宣传单独维护一套 UI。

主视觉沿用石墨深色、青蓝重点、克制渐变和高对比的图表；沉浸感来自连续空间、宽工作区和少跳页。动效只反馈真实状态。所有关键页及空态、失败态、取消中、离线态、恢复态一起设计；支持键盘操作与减少动态效果。

## 5. 租赁 GPU 场景的部署与留存

用户交付的是一个预构建版本镜像及启动配置，服务器上不需要克隆源码后重新编译 llama.cpp 和逐包装依赖。首次拉镜像、准备驱动、下载模型、挂载数据仍需要真实时间；不能把“一条命令”宣传成“任何机器几秒可用”。

记录两种实测：全新节点冷部署；已有镜像/模型缓存的启动恢复。驱动和容器 GPU 配置必须通过环境探针。模型缓存、SQLite、种子/合成资产、checkpoint 与产物挂到应用容器外的工作目录。

容器持久卷不等于服务器销毁后仍然保留。关租前提供“导出工作区/导出模型”的明确操作和检查清单；整套工作区导出包含项目元数据、数据资产、配置、评测与需要的产物，恢复到新节点可见且校验完整。基础模型可复用外部持久磁盘或按 revision 重新下载，不默认把大缓存塞进每个项目包。应用不自动替用户退租或销毁服务器。

分机模式仅在有常驻控制节点时有明显价值：保留场景与数据、临时启用 GPU 执行代理。代理只接收执行包、执行、报告事件/产物、管理取消与恢复；没有项目页面、模板、助手、独立业务数据库。但其机器仍需要真实训练依赖和模型文件，“轻代理”指业务职责轻，不代表镜像体积极小。该模式暂列后续，第一版先把内部执行边界留清楚。

## 6. 保持的硬约束

三分类 black/white/gray；reason 强制非空且不超过 200 字符；JEV 两开关独立；seed 按 7:1.5:1.5 划分，合成不进 test；不得用 test 选择模型/调参；默认 Q4_K_M；性能先于效果；模型范围保持轻量 1.5B–3B；脱敏不可逆；全链路 sc_/ds_/syn_/mv_ 与执行证据关联；前端业务术语映射；数字来自测量或有来源的估算。

版本 lineage 中 syn 可空，但“未合成”必须明确。输出评分/置信度没有监督时不生成固定“正确答案”；单样本理由不冒充特征归因。示例指标不等于真实业务效果。开启兼容仅验证仓库已知片段，L2/L3 等官方规范到位再做。

## 8. 未决项与批准边界

Q1：端到端性能从平台 API 收到请求到完整合规 JSON 返回计时；同机模式含平台/内核排队和解析，分机模式还含节点网络。原始目标保留待定，不承诺 P95 已达标。

Q2：通用合成有效性和风险阈值只在明确任务与数据条件下验证，不能从名称描述自动推断“安全”。

Q3：普通决策训练/推理和仓库片段格式验证不等待官方 JEV 全文；官方 L2/L3 延期。此项仍需随方案批准解除旧文档对普通推理的一揽子阻塞。

Q4：原反诈字段问题退出本阶段依赖；改为确认第一条通用种子数据契约和依据监督。真实业务上线效果仍按用户数据独立验收。

Q5：许可只记录来源与版本，不替代法务结论。Q6：实施时明确可访问 GPU 环境、镜像分发与关租前数据保存方式。

本轮采用用户提出的自定义场景、七步工作台与无助手范围，推荐一体部署为首交付；尚未获整体执行批准，也未连接服务器或购买资源。
