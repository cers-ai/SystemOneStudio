# 示例数据集

这些文件由 [`tools/gen_datasets.py`](../tools/gen_datasets.py) 生成，不是手写维护的。用途是让业务用户**不准备任何数据也能体验全流程**（需求方案.txt 5.2「提供示例数据集，零数据也能体验」）。

```bash
uv run python tools/gen_datasets.py            # 重新生成
uv run python tools/gen_datasets.py --check    # 校验仓库里的文件是否与生成器一致
```

每个文件用独立随机种子，所以新增一个数据集不会改动其他文件的字节内容。

---

## ⚠️ 数据是虚构的，不要当真实数据用

所有身份证号、手机号、银行卡号都是随机生成的，**位数格式合法但不对应任何真实身份**。它们的用途是让脱敏逻辑（`son_data_pipeline.masking`）有东西可脱敏。

**反诈场景的字段名是占位模板。** 需求方案.txt 5.1 写的是 32 个字段，但真实字段规范至今没有提供（`技术方案.md` Q4）。这里生成的是一套覆盖需求点名的三类信息——账号属性 / 交易特征 / 设备信息——的自洽字段集，拿到真实规范后应整体替换。

## 目录

### `fraud/` 反诈账户判定

平台本阶段唯一打通端到端的场景。

| 文件 | 行数 | 用途 |
|---|---|---|
| `seed_200.csv` | 200 | 快速验证全流程，几分钟内跑完 |
| `seed_2000.csv` | 2000 | 更接近真实训练所需的数据量 |

21 列，含 4 个敏感字段（`id_card` / `phone` / `bank_card` / `account`）用于验证脱敏。

标签分布约 **黑 45% / 白 30% / 灰 25%**。三类都有样本是刻意的——需求 5.2 自己给的示例数据集是「黑 10000 / 白 5000 / 灰 0」，恰好是灰样本完全不可见的那种分布；示例数据不应该复制这个问题。

三个类的特征分布**真的有差别**（有测试守着）：

| 指标 | 黑样本 | 灰样本 | 白样本 |
|---|---|---|---|
| 夜间交易占比 | 0.35–0.80 | 0.15–0.45 | 0.00–0.20 |
| 跨境/跨区占比 | 0.30–0.90 | 0.10–0.50 | 0.00–0.25 |
| 新设备占比 | 0.40–0.90 | 0.15–0.55 | 0.00–0.30 |
| 拒付次数 | 1–8 | 0–2 | 0 |

如果三类分布完全相同，流水线会通过所有结构检查，但模型无��可学——那比一个明显坏掉的文件更糟。

### `payment/` 支付风控

7 列，含 `card_hash` 敏感字段。用于验证多场景模板下同一套流程。

### `content/` 内容安全

6 列，含 `content` 文本字段。用于验证文本类输入的 prompt 渲染路径。

### `edge_cases/` 边界用例

**每个文件验证一个具体行为**，不是"看起来真实"。它们的用途是让对应代码路径被真正执行过。

| 文件 | 行数 | 验证什么 |
|---|---|---|
| `minimal_8_rows.csv` | 8 | 7:1.5:1.5 在 8 行上退化为单行测试集；取行方式确定（最大类优先）而非看 shuffle 运气 |
| `single_class_black_only.csv` | 40 | 只有黑样本时，黑白比例**不可算**——必须返回「缺少白样本」而不是谎报「已均衡」 |
| `no_gray_label.csv` | 60 | 无灰样本时，质量报告应主动建议补充 |
| `heavy_missing.csv` | 60 | 约 20% 空值，缺失率被真实统计而非按 NaN 消失 |
| `with_outliers.csv` | 80 | 金额列约 15% 离群值，超过 IQR 方法的假设区间 |
| `sensitive_fields.csv` | 30 | 几乎全是敏感字段，脱敏报告应完整且不可还原 |
| `heavily_unbalanced.csv` | 106 | 黑:白 ≈ 50:1，合成比例推荐应接近 50:1 且扩增目标指向白样本 |

## 为什么没有预切分的 train/valid/test

平台自己按 7:1.5:1.5 划分（需求方案.txt 5.3），而「合成数据不进测试集」这条硬性约束正是在划分环节强制的（需求方案.txt 5.4）。

预置切分文件会造成两个问题：

1. **重复了划分逻辑**，两处实现必然漂移
2. **给那条约束开了第二条绕过路径**——外部拿来的 test 文件不经过 `stratified_split` 的断言

所以这里只提供种子数据。切分结果落在 `runtime/workspace/<run_id>/dataset/`。

## 字段语义

`fraud/` 的数值字段：

| 字段 | 含义 | 单位 |
|---|---|---|
| `account_age_days` | 账号注册天数 | 天 |
| `login_count_30d` | 30 天登录次数 | 次 |
| `failed_login_count_30d` | 30 天登录失败次数 | 次 |
| `device_count_30d` | 30 天设备数 | 个 |
| `txn_count_30d` | 30 天交易笔数 | 笔 |
| `txn_amount_mean` | 交易金额均值 | 元 |
| `txn_amount_max` | 单笔最大金额 | 元 |
| `txn_amount_std` | 交易金额标准差 | 元 |
| `night_txn_ratio` | 夜间交易占比 | 0–1 |
| `cross_region_ratio` | 跨地区交易占比 | 0–1 |
| `new_device_ratio` | 新设备交易占比 | 0–1 |
| `chargeback_count` | 拒付次数 | 次 |

文本字段：`device_type` / `region` / `carrier` / `occupation`。

比例类字段（`night_txn_ratio` 等）是浮点数。生成器早期版本用整数采样它们，会在这些列里写出 `0` 而非 `0.35`——足以悄悄破坏任何建立在这些列上的阈值判断。
